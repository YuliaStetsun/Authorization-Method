# Метод auth — Авторизация пользователя

## Описание

| Наименование | auth |
| :--- | :--- |
| **Глагол** | POST |
| **Путь** | `<baseUrl>/auth` |
| **Описание** | Метод авторизации пользователя |

## Входные параметры:

| Параметр | Тип данных | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| email | String | 1..1 | Почта пользователя |
| password | String | 1..1 | Пароль |

## Выходные параметры:

| Параметр | Тип данных | Описание |
| :--- | :--- | :--- |
| accessToken | String | JWT токен доступа |

---

## Основной алгоритм:

**Шаг 1.** 
Система валидирует входные данные. Если успешно, то система переходит к **следующему шагу**. Иначе, к **AC0**.

**Шаг 2.** 
Система ищет запись в таблице `users`: `select * from users where email = input.email AND users.is_archived = FALSE`.
Если запись найдена, система переходит к **следующему шагу**. Иначе, к **AC1**.

**Шаг 3.** 
Система хеширует входной параметр `password` и сравнивает с `users.password_hash`, где `users` - запись, найденная в **шаге 2**. Если пароли совпадают, то система переходит к **следующему шагу**. Иначе, к **AC2**.

**Шаг 4.** 
Система формирует выходные параметры и завершает сценарий с http-кодом 200. Выходные параметры:
* `accessToken` = Формирует система

## Альтернативные сценарии:

### AC0. Ошибка валидации входные данные

| № | Действие | Ошибка |
| :--- | :--- | :--- |
| 1 | Система формирует выходные параметры:
• `error` = -
• `message` = "Входные параметры не прошли валидацию"
• `code` = B000 | B000 |
| 2 | Система возвращает ответ с **HTTP-кодом 400** и завершает сценарий. | — |
